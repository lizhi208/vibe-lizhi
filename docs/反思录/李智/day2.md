今天主要巩固了 Git 版本控制流程，并完成了项目电梯稿单页网站制作（frontend/index.html），进一步理清了自己课程要练成的能力目标。
之前对 Git 的工作流程不熟练，出现了分支名错误、忘记 add 就直接 commit 等问题——实际报错是 git commit 时提示 "Changes not staged for commit"（未 git add），以及 push 时因分支名不一致被拒。通过排错真正理解了 add 暂存 → commit 本地提交 → push 远程推送 的完整逻辑。今日提交（可验证）：cb298e9 day2 提交今日反思录、17b2164 day2 更新完整反思录内容；封卷轻量 tag day2 指向 17b2164。远程仓库 https://gitee.com/lz208/vibe-lizhi.git ，分支 master。
在项目认知上，我学会了从真实用户痛点出发设计产品，不再盲目堆功能。明确了二手集市 AI 项目的最小闭环（发布 → 列表/搜索 → 详情 → 下单锁定，不做支付/物流）、核心功能（AI 生成标题详情、AI 参考报价、AI 应答买家咨询）、风险点（AI 输出质量不稳定）和取舍原则（AI 只出草稿、卖家二次确认、禁止自动提交），懂得先做可落地的最简版本，再考虑进阶功能。电梯稿已落成单页 index.html，和 AI 协作时先让它读 PRD 再写代码，避免了堆功能。
今天最大的收获是养成了先思考边界，再动手开发的工程思维，明白了做项目不是越多功能越好，而是稳定、可用、可演示最重要。后续我会继续熟练 Git 操作，规范每次提交，为后续前后端开发和 AI 接口对接打好基础。
