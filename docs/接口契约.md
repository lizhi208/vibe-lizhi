# 接口契约｜二手集市 + AI 卖家助手

> 本文件是前后端与契约测试的**唯一事实源**。所有端点统一前缀 `/api`。
> 统一响应结构：`{ "code": number, "message": string, "data": any }`
> - 成功：HTTP 2xx，`code = 0`
> - 失败：HTTP 4xx/5xx，**响应体 `code` 与 HTTP 状态码一致**（如 409 冲突时 body.code 也是 409）

## 0. 通用错误码

| HTTP/body code | 含义 | 触发场景 |
| --- | --- | --- |
| 400 | 参数不合法 | 缺必填、类型错、负数、非法枚举、关联数据不存在（外键约束） |
| 401 | 未登录 | 骨架期不使用（免登录） |
| 404 | 资源不存在 | 商品/订单 id 不存在、未匹配路由 |
| 409 | 状态冲突 | 重复下单、重复成交、唯一键冲突 |
| 500 | 服务器内部错误 | 未预期异常（不应在正常输入下出现） |

## 1. GET /api/health

健康检查。无参数。
- 200：`data = "pong"`

## 2. GET /api/categories

全部分类，按 `sort_order, id` 升序。
- 200：`data = [{ id, name, sort_order }]`（初始 5 项）

## 3. GET /api/products

旧列表（保留兼容）：在架商品（ON_SALE/LOCKED），`created_at DESC`，最多 50 条。
- 参数（均可选）：`keyword`（标题/描述模糊匹配）、`categoryId`
- 200：`data = [商品卡片]`，卡片字段 `{ id, title, price, image_url, status, created_at }`

## 4. GET /api/products/page —— 分页列表

- 参数（均可选）：
  - `page`：正整数，默认 1
  - `size`：正整数，默认 10，最大 50
  - `keyword`、`categoryId`：同旧列表
- 排序：`created_at DESC, id DESC`（日期倒序，id 保证次序稳定）
- 200：
```json
{ "code": 0, "data": {
  "list": [商品卡片],
  "pagination": { "page": 1, "size": 10, "total": 23, "totalPages": 3 }
}}
```
- 错误码：
  - 400：`page` 为 0/负数/小数/非数字（如 `abc`、`1.5`、`1e2`）
  - 400：`size` 同上，或 `size > 50`
  - 空串 `page=` 视为未传，用默认值（不报错）
  - 超出实际页数（如 page=999）：200，`list=[]`（空页不是错误）

## 5. GET /api/products/:id

商品详情。
- 200：`data = { id, seller_id, category_id, title, description, image_url, price, reference_price, status, created_at }`
- 404：id 不存在

## 6. POST /api/products —— 发布商品

body：`{ title, price, categoryId, description?, imageUrl?, referencePrice? }`
- 201：`data = 商品详情`，message「发布成功」，新商品状态 ON_SALE
- 400：title 缺失/空白；price 非有限数或负数；categoryId 缺失
- 400：categoryId 指向不存在的分类（外键约束 → 参数错误）

## 7. PUT /api/products/:id —— 编辑商品

body 为要更新的字段子集：`{ title?, price?, categoryId?, description?, imageUrl?, referencePrice? }`
- 200：`data = 更新后的商品详情`；空 body 为 no-op，返回当前商品
- 404：id 不存在
- 400：title 空白；price 非有限数或负数；categoryId 指向不存在分类；referencePrice 非法

## 8. POST /api/orders —— 下单锁定

body：`{ productId, buyerId? }`（buyerId 缺省为演示买家 2）
- 201：`data = { orderId, productId, status:"LOCKED" }`；商品 ON_SALE→LOCKED，订单 LOCKED
- 400：productId 缺失/格式非法（如 `abc`、`-1`、`1.5`）；buyerId 格式非法或指向不存在的买家
- 409：productId 正整数但商品不存在、已被锁定或已成交（条件更新 affectedRows=0），**body.code 必须为 409**

## 9. PATCH /api/orders/:id/deal —— 标记成交

- 200：`data = { orderId, productId, status:"DEAL" }`；订单 LOCKED→DEAL，商品 LOCKED→SOLD
- 404：订单 id 不存在
- 409：订单不是 LOCKED 状态（重复成交等）

## 10. POST /api/ai/draft —— 图片生成草稿（multipart/form-data）

- 字段：`image`（单个文件），仅允许图片，大小 ≤ 5MB
- 200：`data = { title, description, referencePrice }`（待接入第三方，当前未配置时为 5xx/明确错误，前端引导手填）
- 400：未上传文件；文件超过 5MB；非图片类型

## 11. POST /api/ai/answer

骨架期未实现。
- 501：`{ code:501, message:"AI 应答待实现（P1）" }`

## 12. GET /api/stats/overview

- 200：`data = { total, byCategory:[{name,value}], byStatus:[{status,count}] }`，value/count/total 均为数字

## 13. POST /api/stats/visit

body：`{ path? }`（缺省记为 `/`，截断 200 字符）
- 200：该 path 访问量 +1，`data = [{path, views}]`

## 14. GET /api/stats/visits

- 200：`data = [{path, views}]`，按 views 降序，最多 20 条

## 15. 未匹配路由

- 404：`{ code:404, message:"接口不存在", data:{ path } }`
