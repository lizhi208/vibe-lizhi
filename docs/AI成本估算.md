# AI 成本估算表｜/api/ai/draft 月度账本

> 大四做项目也要有账本：大模型按 token 计费，上线前先算清月度成本与额度上限。
> 模型：阿里云百炼 `qwen-vl-max`（OpenAI 兼容模式）。价格以百炼官网公开页为准，以下为 2026-10 查询值。

## 1. 单价（百炼 qwen-vl-max，北京地域，按量付费）

| 计费项 | 价格 | 单位 |
| --- | --- | --- |
| 输入 | 1.6 元 | 每百万 tokens |
| 输出 | 4 元 | 每百万 tokens |

（更便宜的平替：`qwen-vl-plus`；换模型只需改 `.env` 的 `AI_MODEL`，零改码。）

## 2. 单次调用 token 假设

| 项目 | 估算 | 依据 |
| --- | --- | --- |
| 图片输入 | ≈ 1200 tokens | 手机照片按 qwen-vl 图像切分规则（28×28 切块），普通照片约 1~1.5k |
| 提示词输入 | ≈ 250 tokens | 系统提示词（见 `backend/src/services/ai.prompts.js`）+ 用户指令 |
| 输出 | ≈ 200 tokens | 约定 JSON：30 字标题 + 200 字描述 + 参考价 |

**单次成本** = 1450 × 1.6/1,000,000 + 200 × 4/1,000,000 ≈ **0.0031 元/次**（不到半分钱）。

## 3. 月度成本估算表

| 场景 | 月调用次数 | 月输入 tokens | 月输出 tokens | 月成本（元） |
| --- | --- | --- | --- | --- |
| 课程演示期（自己+同学试用） | 50 | 7.25 万 | 1 万 | ≈ 0.16 |
| 小规模上线（每天 30 次发布） | 1,000 | 145 万 | 20 万 | ≈ 3.12 |
| 运营增长（每天 300 次） | 10,000 | 1,450 万 | 200 万 | ≈ 31.20 |

公式：`月成本 = 月调用次数 ×（平均输入 tokens × 输入单价 + 平均输出 tokens × 输出单价）`

## 4. 额度上限与降级策略（我定的）

- **月度预算上限：20 元**（约 6,000 次调用），在百炼控制台设置消费告警/限额。
- 新用户免费额度足够覆盖课程演示期，**额度不是问题，泄露才是问题**：Key 只在后端 `.env`，不进 git（已 gitignore）、不进前端。
- 兜底：未配置 Key / 超时 5s / 上游错误 / 欠费 → 接口统一 502 降级，前端提示「可手动填写」，发布闭环不断（契约 §10）。

## 5. 结论

按课程演示规模，月成本 < 0.2 元；即便小规模运营也不到一杯奶茶钱。风险不在费用，在 Key 泄露与异常调用——已用「Key 不出后端 + 5s 超时 + 502 降级」三重兜底覆盖。
